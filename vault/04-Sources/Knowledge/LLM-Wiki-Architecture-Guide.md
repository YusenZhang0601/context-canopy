# LLM Wiki 架构指南 (LLM Wiki Architecture Guide)

本文档是关于 LLM-Wiki 与个人 AI 基底系统设计原理的权威原始技术指南。

## 1. 核心设计思想

传统知识管理面临着两大痛点：
1. 人工维护成本过高，随着笔记数量增加，知识库逐渐荒废。
2. 传统 RAG（检索增强生成）依赖临时切片检索，缺乏对全局知识概念的结构化梳理与长期演化维护。

LLM-Wiki 架构通过将不可变的原始来源层（Sources）与可编译、可互相链接的主图谱层（Canonical Graph）解耦，让 AI Agent 承担知识的提炼、查重、双向链接建立与索引维护工作。

## 2. 系统分层模型

- **00-Inbox**：临时捕捉区，存放未经处理的灵感与临时材料。
- **04-Sources**：不可变证据层，保存原始论文、技术规范、会议记录与对话记录。
- **01-Knowledge**：客观知识与方法论。
- **02-Insights**：价值观、工程哲学与深度洞察。
- **03-Personal**：个人档案、协作体系与长期登山模型。
- **90-System**：编译工具、校验规范、模式定义与操作日志。

## 3. 架构特征与收益

1. **确定性与可复现性**：通过编译器定期审计图谱连通性、孤岛节点与死链。
2. **跨 Agent 共享**：解耦单一 LLM 宿主，所有 Agent 共享统一的本地 Markdown 知识资产。
3. **可追溯性**：每张知识卡片均具备明确的来源双链，确保任何结论均有据可查。
